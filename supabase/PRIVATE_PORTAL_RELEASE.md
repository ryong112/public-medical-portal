# 문서 비공개·사진 분석 권한 배포 점검

이 문서는 운영 변경 지시가 아니라, 배포 승인 후 사용할 순서입니다. 포털 프리뷰는 로컬 테스트 데이터에서 확인합니다.

1. 운영 Supabase Storage에서 `files`의 공개 플래그와 파일 정책을 읽기 전용으로 점검합니다. 필요하면 로그인된 CLI에서 `supabase db query --remote --read-only "select id, public from storage.buckets where id = 'files';"`로 확인합니다. 비밀번호·토큰을 공유하지 않습니다. 기존 문서 수와 저장소 원본의 백업·복원이 가능한지 확인합니다. 테스트에는 실제 내부 문서를 쓰지 않습니다.
2. 테스트 환경에서 `20261125090000_private_portal_documents_ocr.sql`을 적용한 뒤 인증된 담당자가 새 파일 업로드, 오래된 문서 열기, PDF/이미지 미리보기, 일반 다운로드와 폴더 ZIP을 확인합니다. 앱은 기존 URL을 문서함 객체 키로만 해석하며 원본 URL을 요청하지 않습니다. 외부 호스트 링크를 문서에 등록해 파일로 열던 동작은 허용하지 않습니다. 예전 링크와 호환되지 않는 문서가 있는지 파일 수/경로 형태만 점검합니다.
3. 같은 환경에서 새 `analyze-whiteboard` Edge Function을 기본 JWT 검사와 함께 배포하고 승인된 팀원 기기에서 합성 사진 1개를 분석합니다. 미승인·차단·전광판 기기는 분석과 교정 저장 권한이 없어야 합니다. 실제 사진의 외부 처리에 적용되는 기관 승인과 Gemini 계약은 별도로 확인합니다.
4. 운영 적용 승인을 받은 뒤 새 문서 등록 정책 SQL과 앱 배포를 같은 작업 시간에 진행합니다. 이때 예전 화면에서 새 업로드를 진행하지 않도록 안내합니다. 운영 Supabase **Storage 설정**에서 `files`를 비공개로 전환합니다. SQL 마이그레이션은 저장소 메타데이터를 직접 변경하지 않으므로, 이 단계가 빠지면 기존 공개 주소는 차단되지 않습니다. 문서가 이미 비공개라면 상태 유지 및 검증만 합니다. OCR 함수 배포도 별도 단계입니다.
5. 비공개 전환 후 승인 사용자로 합성 파일을 열 수 있고, 같은 파일을 공개 경로나 미승인 세션에서 열 수 없는지 확인합니다. 지원하는 Supabase CDN 무효화 경로를 확인하고, 이미 공개된 주소가 있었던 경우 기존 캐시와 문서 보안 영향을 별도로 평가합니다.

장애 때 공개 버킷을 다시 켜는 것을 기본 되돌리기로 삼지 않습니다. 비공개 상태를 유지하고 인증 경로를 고친 뒤 문서 개수와 예전 기록을 확인합니다.
